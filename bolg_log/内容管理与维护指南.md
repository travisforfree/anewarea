# 内容管理与维护指南

更新日期：2026-09-16。本指南对应本次重构后的源码；《博客源码框架总结.md》保留为重构前的历史分析。

## 1. 这次改了什么

- 移除两篇旧文章、旧照片在首页及图库中的引用，以及原来写死的首页短句。
- 清空内容，保留首页、文章、照片、音乐、视频、分类、归档和 404 页面。各入口即使没有内容也能打开。
- 增加位于 `/anewarea/admin/` 的网页管理后台，支持登录、文件选择、编辑、草稿、发布、删除及内容搜索。
- 统一所有内容的 Markdown 存储方式，不再让首页图库和完整图库各维护一份图片清单。
- 增加多级分类，允许一条内容放入多条分类路径。
- 评论只在允许评论的内容详情页加载一次；列表、后台和空页面不加载。
- 用浏览器原生功能替换旧 jQuery、Fancybox 和复制库，保留图片放大、移动导航与代码复制。
- 数学公式按文章的 `math` 开关启用；移除未使用的 KaTeX 资源。
- 移除对全文做正则替换的标点过滤器，避免改写代码块和原始内容。
- 移除密码文章插件。后台不提供私密内容功能，构建遇到密码文章会明确报错。
- 构建前清理旧产物；新增测试及拉取请求检查，运行环境统一到 Node.js 24。

这些是源码层面的变化。线上生效需要将改动推送到 main，并由 GitHub Actions 成功发布。本指南不把本地构建成功当作线上发布成功。

## 2. 第一次登录后台

网站更新后，打开博客页脚的「管理」，或访问：

[博客管理入口](https://travisforfree.github.io/anewarea/admin/)

目前采用 GitHub 细粒度访问令牌登录，不需要另租服务器，也不用把 GitHub 密码交给博客。

### 创建令牌

1. 在 GitHub 登录你用于管理博客仓库的账号。
2. 打开 [创建细粒度访问令牌](https://github.com/settings/personal-access-tokens/new)。
3. 设置一个容易辨认的名称，例如「我的博客后台」，选择有效期。
4. Repository access 选择 **Only select repositories**，只选择 **anewarea**。
5. Repository permissions 中，将 **Contents** 设置为 **Read and write**；Metadata 保持默认读取权限。
6. 生成令牌，粘贴到后台登录框。

这是一次仓库访问授权，不是新建博客账号。令牌到期或被撤销后，需要重新创建。GitHub 对权限与有效期的解释见 [官方令牌文档](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。

令牌只保留在当前页面内存中，不写入源码、Cookie、localStorage 或 sessionStorage。退出登录、刷新或关闭页面后需要重新登录。不要把令牌填进文章正文或站点配置。

### 登录后看到什么

左侧是已发布内容与草稿列表，可以按标题、内容类型或分类搜索；右侧是编辑表单。点击已有内容可修改，新建内容会生成独立标识及稳定链接。

后台直接操作 GitHub 仓库，因此即使从本地预览打开后台，使用真实令牌点击保存，也会修改真实仓库；本地预览不是离线草稿箱。

## 3. 发布文章

1. 点击「新建内容」，选择「文章」。
2. 填写标题、发布日期、简短介绍和正文。
3. 按需填写分类和标签。
4. 可选择图片，后台会把图片引用插入 Markdown 正文。
5. 按需开启评论、目录或数学公式。
6. 点击「发布内容」。

简短介绍用于首页和列表预览。正文支持 Markdown；图片插入后可以把默认的「图片」改成有意义的图片说明。

「包含数学公式」只控制这条内容是否加载公式渲染资源。「显示目录」根据文章标题结构生成目录。两者默认关闭。

发布日期不能晚于当前时间；想提前写内容时，请先保存为草稿。

## 4. 上传照片：不再经过 PicGo

1. 新建内容，选择「照片」。
2. 填写这组照片的标题，例如「一次散步」。
3. 点击「选择照片」，可以一次选择多张图片。
4. 填写分类和文字说明，点击发布。

上传后照片与博客内容保存在同一个仓库中。首页预览、照片分区和详情页都读取同一条内容，无需复制图床链接，也不需要编辑图库页面的 HTML。

你还可以在「照片链接」框中调整顺序、移除某张图片的展示，或填入已有的 HTTPS 图片地址。列表用第一张照片作为预览图。

当前支持 JPG、JPEG、PNG、WebP、GIF、AVIF。后台不自动压缩、转码或去除照片元信息，上传前可自行处理大图；手机 HEIC 照片需先导出为支持的格式。

单文件上限是后台设置的 **20 MiB**，一次最多 **12 个附件、合计 60 MiB**。这些是本站为了控制上传体量设置的限制，不是对 GitHub 所有文件限制的概括。

## 5. 分享音乐

新建「音乐」内容，可以采用两种方式：

| 方式 | 填写内容 | 读者体验 |
| --- | --- | --- |
| 平台分享链接 | 歌曲或专辑的完整 HTTPS 分享链接 | 点击后去原平台打开 |
| 音频文件 / 文件直链 | 选择音频文件，或填入可直接访问的音频 HTTPS 地址 | 在本站使用播放器播放 |

可以填写歌手、封面、推荐理由、分类和标签。两种方式可以同时填写。

平台分享页不是音频文件直链，不要将普通歌曲页面地址填入「文件直链」。本站不会解析平台加密音源或自动下载平台歌曲。平台链接的登录、会员或地区要求由原平台决定。

支持上传 MP3、M4A、OGG、WAV、FLAC、AAC；浏览器是否能播放仍取决于实际编码。MP3 通常更便于跨设备分享。

## 6. 上传与分享视频

新建「视频」内容：

- 短视频可以直接选择文件上传，发布后详情页显示播放器。
- 已经上传到视频平台的内容，可以粘贴平台分享链接。
- 如果有可直接访问的视频文件 HTTPS 地址，可以填写文件直链。
- 可单独选择封面图片，作为列表预览和视频封面。

当前接受 MP4、WebM、OGV、MOV，推荐使用 **MP4 容器、H.264 视频和 AAC 音频**。上传成功不等于任意编码都能在所有浏览器播放；本站不提供视频转码或自适应流媒体服务，详情页保留打开原文件的入口。

超过本站 20 MiB 单文件上限的视频，优先使用平台链接或其他已托管的视频直链。GitHub Pages 适合静态网站，发布站点还有总体大小和带宽约束，详见 [GitHub Pages 官方限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。

## 7. 多级分类怎么用

「内容类型」与「分类」是两个维度：文章、照片、音乐、视频决定内容如何展示；分类决定内容属于什么主题。

在分类框中用 `/` 分隔层级，例如：

~~~text
生活 / 旅行 / 深圳
~~~

会形成：生活 → 旅行 → 深圳。你可以给照片使用这条路径，也可以给相关的文章使用同一路径。

一条内容想进入多个分支时，每行写一条路径：

~~~text
音乐 / 爵士 / 现场
收藏 / 2026
~~~

这些分类不需要提前建立。发布内容后，分类树自动生成；删除某个分类下的最后一条内容后，这个空分类也会消失。

每条路径最多 8 层。标签不表示父子关系，适合填写「夏天」「夜晚」等横向标记，用逗号分隔。

底层沿用 Hexo 的分类语义：平铺数组表示一条父子路径，嵌套数组表示多条路径。参见 [Hexo Front Matter 文档](https://hexo.io/zh-cn/docs/front-matter)。

## 8. 草稿、修改、删除和链接

### 草稿

点击「保存为草稿」会将 Markdown 保存在 `source/_drafts/`。它不会出现在网站的首页、分类和归档中，但仍是仓库里的文件。附件保存在公开资源目录，不因正文是草稿而私有。

把已发布内容保存为草稿，会从网站下架；后台会在这个操作前确认。之后重新发布时，仍然使用原来的内容链接。

### 修改

从左侧打开内容，修改后点击「保存并发布」。后台保留原文件名与永久链接；修改标题、分类和日期不会使后台新建内容的 `entries/<id>/` 地址变化。

如果有人在编辑期间更新了仓库，后台会停止保存并提示重新读取，而不会强制覆盖新的提交。可先下载编辑文字备份或复制正文，再刷新、重新打开内容合并修改。

### 删除

点击「删除内容」会移除对应 Markdown，自动发布成功后，内容从网站消失。已有附件不会跟着删除，以免破坏其他文章的引用；不再需要的附件可在确认引用关系后单独整理。

本次清空博客移除了旧文章和旧照片引用，并从独立的 `blog-images` 仓库当前 `main` 分支删除了旧原图 `DSC_1712.JPG`。两个仓库都没有重写 Git 历史，因此旧提交仍保留恢复能力。

## 9. 点击发布之后发生什么

1. 后台读取仓库当前版本。
2. 上传当前内容引用的新附件和 Markdown 文件。
3. 创建一次包含这些修改的提交。
4. 以不强制覆盖的方式更新 main 分支。
5. GitHub Actions 安装依赖、运行检查、构建并发布。

文件上传失败时，不会先把只有半套附件的内容提交到发布分支。仓库在过程中被其他人更新时，分支更新会被拒绝，需要重新读取后再保存。

实现参考 GitHub 的 [Git Trees 接口](https://docs.github.com/en/rest/git/trees) 和 [Git References 接口](https://docs.github.com/en/rest/git/refs)。

后台提示「内容已提交」意味着仓库保存成功，不等于网站已经更新。点击「查看发布进度」查看 Actions，发布成功后再刷新网站。本站没有假装实时跟踪部署状态，也不会把尚未完成的部署提示为成功。

## 10. 配置与维护入口

| 项目 | 位置 |
| --- | --- |
| 站名、副标题、URL、根路径 | 根目录 `_config.yml` |
| 后台仓库、分支、单文件上限 | `_config.yml` 的 `content_admin` |
| 导航、评论配置、数学开关 | `themes/mashiro/_config.yml` |
| 内容分区、空首页与归档 | `scripts/content.js` |
| 后台表单和上传交互 | `source/admin/` |
| 文章与媒体详情 | `themes/mashiro/layout/_partial/article.ejs`、`media.ejs` |
| 通用卡片与内容分区 | `content-card.ejs`、`content-index.ejs` |
| 内容相关样式 | `themes/mashiro/source/css/_partial/content.styl` |
| 发布检查 | `.github/workflows/deploy.yml` |

`content_admin` 中只能保存公开配置，不要添加令牌。更改仓库、分支或站点路径后，需要重新构建，并确认工作流监听的分支与后台写入分支一致。

评论目前继续使用原 Giscus 仓库设置，详情页可以按条关闭评论。Giscus 的仓库安装授权和 Discussions 分类是否有效，仍需在真实线上环境确认。

## 11. 本地与网页后台一起使用时

网页后台的修改直接发生在 GitHub，而不会自动写回你的电脑。之后要在电脑上改代码或内容，应先同步远程仓库，再编辑与推送，避免使用旧副本覆盖网页后台的修改。

正常命令：

~~~sh
npm ci
npm test
npm run build
npm run server
~~~

使用 Node.js 24；`npm run build` 会清理旧生成结果，然后重新生成。请不要手工修改 `public/`，因为下一次构建会覆盖它。
